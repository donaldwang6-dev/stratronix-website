**Enterprise system integration**: Legal workflows need document management integration. Medical workflows need EHR integration. Financial workflows need CRM and risk system integration. The model is the last mile. The integration is where enterprises actually live.

**Business continuity**: What happens when the model vendor changes their terms? What happens when the fine-tuning methodology gets challenged? Enterprises need architectural control, not just inference control.

## What Enterprise On-Device AI Actually Requires

The companies building production on-device AI in regulated industries aren't just picking the fastest model. They're building a compliance architecture:

- **Authentication**: Who accessed the system? Multi-user, role-based, auditable.

- **Audit trail**: What did the AI do with that data? Full prompt/response logs stored locally.
- **Data residency**: Where is the data? Proving it never left the building.
- **Business continuity**: Who controls the architecture? Open-source agent framework = no vendor lock-in.

The cost of getting this wrong just went up significantly. The question for regulated-industry buyers is no longer "can we do on-device AI?" It's "can we prove we're compliant?"

## The Architecture That Satisfies Both Questions

The answer is a hybrid architecture:

- **On-device**: ARM-class hardware, Linux, full local data storage. All user data, documents, session history.
- **Cloud LLM gateway**: BYO API keys for OpenAI, Anthropic, DeepSeek, Mistral. LLM vendor processes intelligence, not data.
- **Enterprise layer**: Multi-user authentication, audit logs, MCP integration, compliance documentation.

This is what STA-100 implements. The model can change. The compliance framework stays.
